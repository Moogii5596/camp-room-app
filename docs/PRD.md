# Өрөө бүртгэлийн вэб апп — хөгжүүлэлтийн төлөвлөгөө
> Эх баримт: 2026-11-18, @Алтан-Эрдэнэ. Энэ файл = **шаардлагын ганц эх сурвалж**. Бүтнээр нь бүү унш — `docs/CONTEXT.md`-ээр хэрэгтэй §-ийг л.

## §1. Зорилго ба хамрах хүрээ
Одоогийн Expo (React Native) аппыг вэб апп болгож Cloudflare-ийн үнэгүй багц дээр байршуулна. 2 хэрэглэгч нэг өгөгдлийн санг хамтдаа ашиглана. Дата Excel-ээс ачаалагдаж, шинэчлэгдэнэ. Өөрчлөлт бүр цагийн тэмдэгтэй бүртгэгдэж, тайланд гарна.

**Хамрах:**
- Одоогийн дэлгэц, үйлдлүүд вэбд: өрөөний жагсаалт, ээлжээр шүүх, хайлт, ажилтан нэмэх, өрөө солих, кемпээс буулгах
- Өгөгдлийг SQLite-аас Cloudflare D1 руу. Нэвтэрсний дараа апп = үндсэн эх сурвалж
- Ирцийн болон ээлж солилцооны Excel импорт
- Ээлжийн хуваарь, түүнд суурилсан R-ийн автомат бөглөлт
- Ээлжийн бусаар ирсэн/явсныг бүртгэх (нэг нэгээр эсвэл бөөнөөр)
- Өөрчлөлт бүрийг цагийн тэмдэгтэй бүртгэж тайланд гаргах
- Тохиргоо: ээлжийн хуваарь, ээлж/туслан гүйцэтгэгчийн код, жолоочдын өрөө
- Сүлжээгүй үед нэвтрэх (PWA кэш)
- `camp.gobiverse.website` дээр байршуулах, түр нэвтрэлт, роботоос хамгаалалт

**Хамрахгүй:** утасны апп, хэрэглэгч бүрийн бүртгэл, эрхийн түвшин (нэг түр нэвтрэх нэр), төлбөртэй багц.

**Одоогийн байдал:** Expo SDK 57, expo-router, react-native-web. Дата expo-sqlite-д. Анхны дата `src/assets/rooms_master.xlsx` (147 өрөө), `employee.xlsx` (644 ажилтан). Бүх логик `src/app/index.tsx` (828 мөр), `src/services/database.ts`.

## §2. Датаны эх сурвалж
Хоёр төрлийн Excel: **ирцийн файл** (`docs/Өрөө бүртгэл.xlsx`-тэй ижил бүтэц) ба **ээлж солилцооны файл** (`docs/ShiftChange.xlsx`-тэй ижил). Анхны ачаалалт ба шинэчлэлт хоёулаа ирцийн файлаар. Файлын нэр хамаагүй — төрлийг толгойн мөрийн баганы нэрээр танина. Ирцийн файл өдөр бүрийн байршлыг агуулдаг тул апп **өдөр бүрийн байршил, хоолны төлөвийг** хадгална (хамгийн том өөрчлөлт).

**Ирцийн файлыг таних:** толгойд Shift, ID, Овог, Нэр, Албан тушаал ба 1–31 баганууд. Сарыг хуудасны нэрээс (`2026 November`); уншиж чадахгүй бол импортын үед асууна.

|---|---|---|

### §2.2 Өдрийн кодууд
| Код | Утга | Өглөө | Өдөр | Орой | Хэрхэн бүртгэгдэх |
|---|---|---|---|---|---|
| R | Бүтэн өдөр кемпт | ✓ | ✓ | ✓ | Ирсэн/явсан өдрийн хооронд |
| R1 | Оройн хоолны цагаар ирсэн | – | – | ✓ | Ээлж солилцооны «in» → автомат |
| R2 | Өдрийн хоолны цагаар ирсэн | – | ✓ | ✓ | Гараар (ээлжийн бусаар) |
| R3 | Өглөөний хоолны цагаар ирсэн | ✓ | ✓ | ✓ | Гараар (ээлжийн бусаар / ээлжээс өмнө) |
| D1 | Өглөө явсан (ээлжийн автобус) | ✓ | – | – | Ээлж солилцооны «out» → автомат |
| D2 | Өдрийн хоолны дараа явсан | ✓ | ✓ | – | Гараар |
| D3 | Оройн хоолны дараа явсан | ✓ | ✓ | ✓ | Гараар |
| (хоосон) | Кемпт байхгүй | – | – | – | — |

**Тооцоо (апп өөрөө):** Өглөө = R+R3+D1+D2+D3; Өдөр = R+R2+R3+D2+D3; Орой = R+R1+R2+R3+D3; **Ор хоног** = R+R1+R2+R3 (D-тэй өдөр орохгүй). R3 одоогийн Excel-ийн тайлбарт байхгүй — импорт, тайланд нэмж дэмжинэ.

### §2.3 Файлд илэрсэн, импортод зохицуулах зүйлс
- 619 ажилтны мөр, 103 өрөөнд. Өдрийн код 25-ны өдөр хүртэл урьдчилан бөглөгдсөн.
- 26 ID тэгээр эхэлдэг (02103); ээлж солилцооны файлд ижил хүн 2103 → ID текстээр, тааруулахдаа эхний тэгийг авна.
- 28 мөрөнд жинхэнэ ID алга: 11 хоосон, 17 бүлгийн тэмдэг (NEW10.28, NEW11.04, NEW11.11, ШИНЭ, Харуул).
- 15 мөрөнд өрөө хоосон, 1 мөрөнд текст (рбарам). 19 мөрөнд ээлж хоосон, 1 мөрөнд кирилл «В».
- Хоолны багануудын томьёо нэг багана шилжсэн (жнь «Өглөөний хоол» = D2+D1+Total) — **апп томьёо уншихгүй**, §2.2-оор тооцно.
- `rooms_master.xlsx` (147 өрөө, төрөл, багтаамж) = өрөөний лавлах. `employee.xlsx` цаашид ашиглахгүй.

### §2.4 Дутуу утга — алдаа биш, төлөвөөр тэмдэглэнэ
| Дутуу талбар | Хадгалах төлөв | Дараа нь |
|---|---|---|
| Өрөө хоосон / танигдахгүй (рбарам) | Өрөөгүй; утгыг `raw_room`-д | Аппаас өрөө оноох / дараагийн импорт |
| Ээлж хоосон | Ээлжгүй | Аппаас / ээлж солилцооны файлаар |
| ID хоосон / бүлгийн тэмдэг | ID-гүй; тэмдгийг `raw_id`-д | Жинхэнэ ID орвол автоматаар солигдоно |
| Албан тушаал хоосон | Албан тушаалгүй | Аппаас засна |
| Өдрийн код бүгд хоосон | Тухайн сард кемпт байгаагүй | Жагсаалтад үлдэнэ |
| Овог, нэр, ID бүгд хоосон | Хоосон мөр | **Алгасна** (цорын ганц) |

Самбар, тайланд эдгээр бүлгийг тусад нь харуулж, хайлтаар шүүнэ. Хэвшүүлэлт: хоосон зай арилгах, кирилл→латин («В»→«B»), томьёо/тайлбарын мөр алгасах.

### §2.5 Ээлж ба ангиллын код (Shift багана)
Туслан гүйцэтгэгчийг шинэ багана нэмэлгүй Shift кодоор ангилна. Кодыг **Тохиргооноос** нэмэх/засах/хасах. Танигдаагүй код ирвэл урьдчилсан харагдацад анхааруулж, тохиргоонд нэмэхийг санал болгоно.

| Код | Утга | Төрөл | Хэрхэн бүртгэгдэх |
|---|---|---|---|
| A, B, C, D | Ажлын ээлж | Үндсэн | Хуваариар (28 хоног) |
| N | Ээлжгүй үндсэн ажилтан | Үндсэн | Гараар |
| NEW | Шинэ ажилтан | Үндсэн | Ээлж оноогдтол гараар |
| W | Дугуйн компани | Туслан гүйцэтгэгч | Гараар, «Туслан гүйцэтгэгч» хэсэгт |
| S | Харуул | Туслан гүйцэтгэгч | Гараар, «Туслан гүйцэтгэгч» хэсэгт |
| BUS | Ээлжийн автобусны жолооч | Туслан гүйцэтгэгч | Ээлж солилцооны импортын дараа тоог оруулна |
| Z | Зочин | Зочин | Гараар |

Шинэчилсэн ирцийн файлд (13:44) харуул 6 мөр S, автобус 7 мөр Bus (912: Автобус 1–4, 913: Баянхонгор 1–3), Z ашиглагдаагүй. Код том/жижиг үсэг ялгахгүй (Bus=BUS, New=NEW), кирилл «В»→B. Танигдаагүй кодтой мөр → зөрчилтэй мөрөнд засуулна. Эх файлын автобусны мөрүүд УБ / Баянхонгор жолооч болж орно.

### §2.6 Импортын зарчим
Нэвтэрсний дараа апп = үндсэн эх сурвалж. Ирцийн импорт анхны утга оруулах, сэргээхэд үргэлж нээлттэй; шинэ сард шинэ файл оруулж болно.
1. Файл сонгоно → агуулгаар төрлийг таньж, одоогийн дататай харьцуулна.
2. Урьдчилсан харагдац: шинэ, өөрчлөгдсөн, **зөрчилтэй** (танигдаагүй код, давхардсан ID, гараар зассан өдөртэй зөрсөн утга) мөрийг тусад нь.
3. Зөрчилтэй мөрийг тэнд нь засах/устгаад баталгаажуулна.
4. Хадгалсан өөрчлөлт бүр цагийн тэмдэгтэй түүхэнд.

### §2.8 ID хэвшүүлэх (хэрэглэгчид дүрэм: нэг хүн = нэг ID, ID баганад өөр зүйл бичихгүй)
1. Тоо (2103), текст («02103»), форматаар угтвартай (X17169) — бүгд хүлээн авна, нүдний бодит утгыг уншина.
2. Хоосон зай, текст угтвар үсгийг хаяж зөвхөн цифр.
3. Харьцуулахад эхний тэг тооцохгүй (2103 = 02103); харуулахад ирцийн файлын бүтэн хэлбэр (02103).
4. Цифргүй (NEW, ШИНЭ, Харуул) / хоосон → ID-гүй, **овог + нэрээр** тааруулна.
5. Нэг ID хоёр өөр нэртэй → зөрчилтэй мөр.

### §2.9 Ээлж солилцооны импортын дүрэм
Мөр бүр `shift_changes`-д; утас, хэлтсийг ажилтанд шинэчилнэ.
- R1/R2/R3 → тухайн өдөр тэр кодоор ирнэ, цаашаа хуваариар R.
- D1/D2/D3 → тухайн өдөр тэр кодоор явна, хойших R-ийг хасна.
- OVERTIME → дараагийн ээлж солих өдөр (Лхагва) хүртэл R сунгана (~7 хоног).
- Өрөө бөглөсөн бол тэр өрөөнд (шинэ ажилтныг өрөөтэй нь нэг импортоор). Өрөөгүй шинэ → «Өрөөгүй ажилтан».
- Дараагийн импортод: сунгасан ажилтан явах болон OVERTIME жагсаалтад байхгүй ч R-ээрээ үлдсэн бол дахин сунгах уу / буух уу гэж асууна.
- Импортын дараа УБ (912), Баянхонгор (913) жолоочдын тоог асууж, ирсэн өдөр R1, маргааш D1.

## §3. Ээлжийн хуваарь ба автомат бөглөлт
28 хоногийн мөчлөг: ирсэн өдөр R1, дараагийн 14 өдөр R, 15 дахь өдөр өглөө D1. Дөрвөн ээлж долоо хоногийн зөрүүтэй: **Лхагва** нэг ээлж ирж, **Пүрэв** өглөө нөгөө нь явна. Ирцийн файлаар баталгаажсан: 11/4 A 128 хүн R1, 11/5 D 126 хүн D1, 11/11 C 113 хүн R1, 11/12 B 101 хүн D1.

**Тохиргооны анхны утга** (Тохиргооноос засна):
| Ээлж | Ирэх | Явах | Дараагийн ирэх |
|---|---|---|---|
| A | 11/04 | 11/19 | 12/02 |
| C | 11/11 | 11/26 | 12/09 |
| D | 11/18 | 12/03 | 12/16 |
| B | 11/25 | 12/10 | 12/23 |

Ээлж бүрт нэг ирэх огноо (anchor), мөчлөг (28), ажиллах хоног (14) хадгална; бусдыг тооцно. Тохиргоо өөрчлөгдвөл **зөвхөн ирээдүйн төлөвлөсөн** өдрүүд дахин тооцогдоно.

**Автомат бөглөлтийн дүрэм:**
1. Ээлжийн ирэлт («in»): ирэх өдөр R1; дараагийн өдрөөс явах өдрийн өмнөх өдөр хүртэл R-ийг `planned` гэж.
2. Ээлжийн бусаар ирсэн (R1/R2/R3 гараар): ирсэн өдрөөс өөрийн ээлжийн явах өдрийн өмнөх өдөр хүртэл R. Жнь B-ийн ажилтан 12/2-нд A-тай хамт ирвэл 12/9 хүртэл R, 12/10-нд B-тэйгээ явна.
3. Явалт («out» → D1, эсвэл гараар D1/D2/D3): явах өдөр R байсан бол D-ээр солиж, хойших урьдчилсан R-ийг устгана.
4. **Гараар зассан өдөр автоматаар дарагдахгүй.** Автоматаар устсан/солигдсон мөр бүр түүхэнд.

Overtime: дараагийн Лхагва хүртэл R; дараагийн солилцоонд out/OVERTIME-д байхгүй бол сунгах/буухыг асууна.

**Автобусны жолооч (BUS):** импортын дараа хоёр төрлийн тоог оруулна; тогтмол өрөөнд ирсэн өдөр R1, маргааш D1.
| Төрөл | Өрөө | Нэр |
|---|---|---|
| УБ жолооч | 912 | УБ жолооч 1, 2, … |
| Баянхонгор жолооч | 913 | Баянхонгор жолооч 1, 2, … |
Төрөл, өрөөг Тохиргооноос өөрчилнө.

## §4. Архитектур
Вэб апп ба API нэг Cloudflare Worker дээр `camp.gobiverse.website`-д, дата D1-д. Нэг түр нэвтрэх нэр/нууц үг. PWA. Бүгд үнэгүй багцад. Excel-ийг браузерт импорт хийж, тайланг браузераар татна — серверт файл хадгалахгүй (R2 хэрэггүй).

| Хэсэг | Технологи | Тайлбар |
|---|---|---|
| Вэб апп | Expo SDK 57 + react-native-web, static export | Одоогийн кодыг хадгална, дахин бичихгүй |
| API | Cloudflare Worker (TS) | Вэбийн файлыг ч хүргэнэ |
| DB | Cloudflare D1 (SQLite) | Одоогийн SQL бараг өөрчлөгдөхгүй |
| Домэйн | camp.gobiverse.website | Worker Custom Domain |
| Сүлжээгүй | PWA: Service Worker + IndexedDB | Файл, сүүлийн дата кэш; засвар дараалалд |
| Нэвтрэлт | Нэг түр нэр + Turnstile | Cloudflare Access-ийг дараа код өөрчлөхгүй нэмнэ |
| Excel | SheetJS (xlsx) | Браузерт уншиж, бэлэн мөрийг API-д |

### §4.1 Нэвтрэлт ба хамгаалалт
Нэр, нууц үгийг кодонд, баримтад **бичихгүй** — зөвхөн Worker secret-д hash-аар.
| Хамгаалалт | Юу хийх |
|---|---|
| Нэвтрэх хуудас | Зөв бол 30 хоногийн HttpOnly, Secure cookie; сүлжээгүй үед ч нэвтэрсэн хэвээр |
| Turnstile | Нэвтрэх хуудаснаас роботыг ялгана |
| Оролдлогын хязгаар | Нэг IP-с 10 минутад 5 буруу → түр хаана |
| Bot Fight Mode | gobiverse.website дээр асаана |
| Хайлтаас нуух | robots.txt + `X-Robots-Tag: noindex` |
Хэн зассаныг **төхөөрөмжийн нэрээр** (тохиргоонд) тэмдэглэнэ.

### §6.1 Тайлангийн хуудсууд
1. **Ирц** — эх файлтай ижил бүтэц (өрөө, ээлж, ID, овог, нэр, албан тушаал, 1–31, кодын тоо, ор хоног, хоол) → дахин импорт хийж болно.
2. **Өөрчлөлт** — огноо, цаг:минут (УБ), хэн, эх сурвалж, ажилтан, талбар, өмнөх, шинэ.
3. **Хураангуй** — өдөр бүрийн кодын тоо, ээлжийн тоо, нийт ор хоног, хоол.

**2 хэрэглэгч зэрэг засах:** нөгөө төхөөрөмж (эсвэл офлайн засвар) саяхан өөрчилсөн бол хадгалахаас өмнө анхааруулж шинэ утгыг харуулна (`updated_at`).

### §6.2 Хэрэглэгчийн ажлыг хөнгөвчлөх нэмэлтүүд (сонгосон 8, ~4 өдөр)
| Функц | Тайлбар |
|---|---|
| Ээлж солих өдрийн самбар | Лхагвад нэг дэлгэцэнд: өнөөдөр ирэх, маргааш явах, сунгасны шийдвэр, жолооч, өрөөгүй, чөлөөлөгдөх өрөө |
| Өрөө санал болгох | Шинэ ажилтанд шинэ ажилтны өрөөнүүдээс (824, 826) сул ортой; үндсэн ажилтанд тухайн ээлжийн өрөөнүүдээс; засвартай/дүүрсэнийг санал болгохгүй |
| Өрөөний тохиргоо | Багтаамж, хос ээлж (A+D / B+C), засвартай, хэн байрлах, компани, шинэ ажилтны өрөө |
| Сарын хоолны тоо | Өдөр бүрийн өглөө/өдөр/орой ба сарын нийт; захиалга илгээхгүй |
| Нэг товчоор буцаах | Сүүлийн засвар эсвэл бүхэл импортыг түүхээс; буцаалт ч түүхэнд |
| Хугацаагаар тайлан | Эхлэх-дуусах огноогоор «Өрөө бүртгэл» загвартай Excel |
| Ухаалаг хайлт | ID/нэрийн хэсэг, өрөө; Viber/Excel-ээс олон ID буулгаж олон сонгох |
| Дүүргэлтийн өнгөт зураг | Сул / дүүрсэн / хэтэрсэн / засвартай |

**Дүүргэлтийн дүрэм:** өрөөг хоёр ээлж хуваалцана, A↔D, B↔C (файлд A+D 42, B+C 28 өрөө; хазайсан 18 өрөө импортод анхааруулгатай). Дүүргэлтийг тухайн шөнө байгаа **нэг ээлжээр** тооцно. Ээлж солих шөнө (ирэх R1, явах маргааш D1) хоёр ээлжийг нийлүүлж хэтрэлт гэж тооцохгүй. Хуваариас гадуур (ээлжийн бусаар, сунгасан) хүн багтаамжид тооцогдоно.

**Утсанд суулгах:** PWA — Android: Chrome → «Апп суулгах»; iOS: Safari → Хуваалцах → «Add to Home Screen». Аппын дотор зааварыг харуулна.

## §7. Хөгжүүлэлтийн үе шат (~22–23 ажлын өдөр)
Явц ба «Зогссон цэг» → `docs/PLAN.md`. Хамгийн чухал нь **2-р үе** (импорт).
1. **Бэлтгэл** (0.5) — wrangler, `web` салбар (одоогийн хувилбарыг хөндөхгүй); Expo SDK 57 баримт; `expo export --platform web` турших
2. **DB + ирцийн импорт** (3) — D1 migration, stay_codes/shift_codes/rooms анхны дата; Excel уншигч (төрөл таних, дутуу төлөв, ID хэвшүүлэх); зөрүү/зөрчил, урьдчилсан харагдацад засах/устгах; ноябрийн файлаар импорт хийж өдрийн нийт дүнг Excel-ийн доод мөрүүдтэй тулгах
3. **Хуваарь + автомат бөглөлт** (2) — огноо тооцох, R урьдчилан бөглөх, явалтаар хасах; ноябрийн бодит датаар тест
4. **API (Worker)** (2) — өрөө, ажилтан, ирэлт/явалт (бөөнөөр), өдрийн код, импорт, тайлан, түүх, тохиргоо; бичдэг зам бүр өөрчлөлт + change_log-ийг **нэг batch**-аар
5. **Вэб UI** (3.5) — database.ts → API клиент; expo-sqlite/file-system/sharing хасах; дэлгэцүүд: Самбар, Ээлж солих өдрийн самбар, Ажилтан, Өрөөгүй ажилтан, Ирэлт/явалт, Туслан гүйцэтгэгч, Хоолны тоо, Импорт, Түүх, Тайлан, Тохиргоо; `Alert.alert` → вэбийн цонх; компьютерийн дэлгэцэнд тохируулах
6. **Ээлж солилцооны импорт, жолооч** (1.5) — in→R1, out→D1; жолоочийн алхам; бусад дүрмийг ярилцсаны дараа
7. **Түүх, тайлан** (1.5) — Ирц/Өөрчлөлт/Хураангуй .xlsx
8. **PWA** (2) — Service Worker, IndexedDB, засварын дараалал, сэргэхэд зөрчил шалгаж илгээх
9. **Байршуулалт, тест** (1.5+0.5) — Custom Domain; нэвтрэлт, Turnstile, хязгаар, Bot Fight, noindex; 2 төхөөрөмж, офлайн, дахин импорт тест; нөөц: D1 Time Travel (7 хоног) + 7 хоног тутам тайлан татах; богино заавар
